## The short version

The token set was minted while this audit ran: 183 Figma variables in 11 collections, mirrored by 12
DTCG files under `packages/tokens/tokens/`. The ladder is real for colour: 82 of 84 semantic values
are aliases into the primitives, the 2 exceptions carry a stated reason, and light and dark are two
modes of one collection with the same 42 names, so dark mode is a remap. It breaks in colour
semantics: 3 solid fills per theme have no paired content colour (`success/default`,
`warning/default`, `danger/default`), and `accent2/on` fails contrast in light (4.04:1). The 42 names
follow two segment orders, and the cost is already visible: the 26 intention-first roles could not
be scoped in Figma and are `ALL_SCOPES`. Nothing consumes a token yet, so fix the pairs and the
names now; every styled component makes both more expensive.

**Lights:** 🟢 2 green · 🟡 5 yellow · 🔴 1 red · 1 not inspected

There is no score. Nine lights on a sheet tell the team where to look; a number out of a hundred
tells them nothing they can act on.

### Check 3 — Naming: YELLOW

- Algorithm found: two. `property/variant` for `bg/*` (6), `text/*` (6), `border/*` (4) = 16;
  `intention/variant-or-property` for `accent/*` (7), `accent2/*` (6), `success/*` (4), `warning/*`
  (4), `danger/*` (5) = 26.
- Matches architecture order: the first group does (property first). The second inverts it.
- Value-named tokens at tier 2/3: 0. Every name survives a brand change and dark mode.
- Synonym pairs: `inverse` / `on`; `subtle` / `muted`; `primary`, `secondary` (rank) alongside
  `subtle`, `default` (dial).
- Tier identifier present: none in code (`color.bg.page`, `color.blue.800`). Tier is carried by the
  file only.
- Figma parity: 42 of 42 semantic names match (`bg/page` ↔ `color.bg.page`).
- Findings:
  - [verified] The split has a measurable cost in Figma. The 16 property-first variables are scoped
    (`FRAME_FILL,SHAPE_FILL`, `TEXT_FILL`, `STROKE_COLOR`). The 26 intention-first variables are
    `ALL_SCOPES`, because a group like `accent/` mixes fills, text and borders and cannot take one
    scope. `accent/text` can be applied as a frame fill.
  - [verified] The same job is filed in two places. Text colour: `text/link` and `accent/text`,
    identical in both themes (Blue/800, Blue/500). Border colour: `border/focus` and `danger/border`.
    Pairing: `text/inverse` and `accent/on`.
  - [verified] `default` means the solid fill in `accent/default` and the mid-strength line in
    `border/default`.
  - [verified] State is a segment in `accent/hover` and a hyphenated suffix in `accent/subtle-hover`.
  - [verified] `accent2` is numbered but is not an interchangeable sibling of `accent`: it has no
    `subtle-hover`, and its passing text step differs.
  - [verified] Disabled is not hoisted: `text/disabled` exists, the disabled fill is folded into
    `bg/muted`, and there is no disabled border.
  - [verified] Scale variables are named by value and repeat across collections (`16` is in Spacing,
    Size, Font size and Line height); the map had to key on `<collection>/<name>` because of it.
- Not inspected: nothing.
- First move: decide one segment order and record it; then rename in the JSON, the variables and the
  map together.

### Check 4 — Color semantics: RED

- Properties: background 6 · content 6 · border 4, plus 26 roles filed by intention
- Intentions present: default, accent (brand), accent2, success, warning, danger, disabled (text
  only) · missing: info, disabled as an intention
- Filled surfaces: `bg/inverse`, `accent/default`, `accent2/default`, `success/default`,
  `warning/default`, `danger/default`, with their hover and pressed states · paired: `bg/inverse`,
  `accent/*`, `accent2/*` · unpaired: `success/default`, `warning/default`, `danger/default`,
  `danger/hover`
- Pairs computed: 85 per theme · failing: listed below
- Subtle/strong dial: holds in light. In dark `bg/subtle` and `bg/raised` are the same step.
- Components sampled: 0 styled components exist.
- Findings:
  - [verified] No token names the content colour for `success/default`, `warning/default` or
    `danger/default`. No existing role can stand in, because the answer flips per theme: in light,
    `warning/default` needs `text/primary` (12.20:1; `text/inverse` gives 1.48:1) while
    `success/default` and `danger/default` need `text/inverse` (6.17:1, 5.14:1; `text/primary` gives
    2.92:1, 3.51:1). In dark all three need `text/inverse` (7.78:1, 12.20:1, 6.81:1).
  - [verified] `accent2/on` on `accent2/default`, light: 4.04:1, below 4.5. The canvas marks it red;
    the token was minted with that value. It passes on `accent2/hover` (5.50:1) and in dark (6.39:1).
  - [verified] `text/placeholder` passes only on the page: 4.66:1 on `bg/page`, 4.28:1 on
    `bg/subtle`, 3.81:1 on `bg/muted` (light); 3.64:1 on `bg/muted` (dark).
  - [verified] `border/control` on `bg/muted`: 2.75:1 light, 2.63:1 dark, against a 3:1 need. It
    passes on `bg/page`, `bg/subtle` and `bg/raised`.
  - [verified] `border/focus` equals `accent/default` in both themes, so a ring drawn against a
    primary button is 1.00:1. Against `bg/inverse` it is 2.96:1 light, 2.20:1 dark. Whether this
    matters depends on the focus-ring offset, which is undecided.
  - [verified] Dark: `bg/subtle` ("hovered rows") and `bg/raised` ("popover, menu") are both
    Neutral/1100, so a hovered row inside a menu is 1.00:1 against its surface.
  - [verified] `success/border` on `success/subtle` is 2.16:1 light / 2.46:1 dark; `warning/border`
    on `warning/subtle` is 2.31:1 / 2.34:1. The canvas marks both as needing no minimum. They fail
    3:1 if the outline is the only thing bounding the box.
  - [verified] `warning/default` on `bg/page`, light: 1.48:1. The dark canvas states "3 for fills";
    the light canvas does not, and this fill would not meet it.
  - [verified] Holding: all 56 ratios stated on the canvas recompute within 0.02. Hover direction is
    correct in both themes. `accent/on` passes on default, hover and pressed in both themes (6.10 to
    12.35:1).
- Not inspected: what components reach for; none are styled.
- First move: mint the three missing content tokens, with a value per theme chosen by the fill's
  luminance.
